# Count-In: maintainer notes

Count-In inserts a drum count-in before a song's first downbeat and can turn guitar and vocals down for a backing track. It ships as a desktop app (PySide6) for macOS arm64 and Windows x64, plus a CLI. The README covers usage; this file covers how it works and where to change it.

## Layout

| Path | Role |
|---|---|
| `src/countin/core/io.py` | ffmpeg/ffprobe I/O, output formats and names, `resource()` for bundle paths |
| `src/countin/core/analyze.py` | beat and downbeat detection, grid fit, attack snap, confidence |
| `src/countin/core/render.py` | click grids (even, build-up, MIDI), sample-accurate mixing |
| `src/countin/core/stems.py` | BS-RoFormer SW separation and stem attenuation |
| `src/countin/core/daw.py` | multitrack export: bar grid from bar 1, parts as float WAV, click and tempo map as MIDI |
| `src/countin/core/zones.py` | whole-song bars, quiet-bar detection, fill-zone clicks |
| `src/countin/core/roformer/` | vendored BS-RoFormer model code (MIT, see its LICENSE) |
| `src/countin/gui.py` | the app: window, waveform, jobs, live preview player |
| `src/countin/help.py` | tips and help sections as plain data, shared by the app and the website |
| `src/countin/update.py` | GitHub release check |
| `src/countin/cli.py`, `verify.py` | CLI and the timing check tool |
| `packaging/` | PyInstaller spec, ffmpeg build, model download |
| `assets/icons/{light,dark}/` | app icons: ICO, ICNS, iconset, PNG 16–1024, raster master |
| `.github/workflows/build.yml` | Windows and macOS builds, smoke test, releases |

## Pipeline

1. **Decode.** `io.decode` pipes float32 PCM out of ffmpeg at the native rate. Clicks get placed on beats found in this same stream, so the source's encoder delay never matters.
2. **Detect.** `analyze.detect` runs beat_this (`final0.ckpt`, 50 fps) on the whole song, about two seconds for three minutes. Peaks get a parabolic sub-frame refinement.
3. **Fit the grid.** `fit_grid` gives each beat a slot index from the median interval, then fits a least-squares line over 16 slots. Slot indexing survives half-time intros; the line averages out the 20 ms frame quantization.
4. **Snap.** `snap_onset` moves the downbeat to the sample-exact attack within ±25 ms. Of several attacks it takes the one nearest the grid.
5. **Bar phase and confidence.** Later downbeats vote on which beat starts the bar. Disagreement yields `alt_downbeat` and a note. `beat_period` rescales the period when the detector counts eighths in 6/8 or half time in 4/4.
6. **Separate (optional).** `stems.separate` runs BS-RoFormer SW in 9.3 s chunks with a Hamming overlap-add, overlap 2. On a Mac the network core runs in Core ML on the GPU (`core/accel.py`): 50 s instead of 93 s with torch MPS fp16 on the demo track, and closer to fp32 (-61 dB against -42 dB). Only band split to masks goes to Core ML; STFT and iSTFT stay in torch. The compiled model gets built from the torch weights on the first run (about 40 s, `accel.export_coreml`) into the data folder; when Core ML fails, torch MPS takes over. On Windows the same core runs from `separator/BS-Roformer-SW-core.onnx` through DirectML (any DirectX 12 GPU; `onnxruntime-directml` is a Windows dependency). The ONNX file sits in the `assets-v1` release and is in `assets.FILES` on Windows only; rebuild it with `python -m countin.core.accel onnx` after a model change and upload it with a new hash. OpenVINO was tested on Intel GPUs and DirectML stayed after tests on NVIDIA and Intel machines; in f16 it also turned silence into NaN, so keep any future backend in f32 or test silence. `COUNTIN_ACCEL` forces a backend. DirectML's default device is adapter 0, the display GPU, which on a laptop with two GPUs is the integrated one; `accel.best_adapter` lists the adapters through DXGI (ctypes, no package) and takes the hardware one with the most dedicated memory, and skips DirectML when only the software rasterizer is there. A backend that fails mid-song (out of memory, driver reset) hands the remaining chunks to torch (`stems.separate`). Every separation logs its time and backend (`stems.last`), the app shows it in the status bar and the CLI prints it. The Neural Engine stays off: the graph does not fit it, Core ML cuts it into about 56 pieces that take 7 minutes to compile and run 20x slower. It returns six stems; the app keeps guitar, vocals, bass, drums and piano (`gui.PARTS`, one slider each with an icon from `part_icon`), and drops "other".
7. **Attenuate.** `stems.attenuate` subtracts `(1 - gain) * stem` from the original. Subtraction keeps the other instruments untouched instead of re-summing stems with their artifacts.
8. **Render.** `render.render` adds the click samples. Every click rounds to a sample from its own float time, so error never accumulates. Silence gets prepended when the song starts too early to hold the count-in.
9. **Encode.** `io.encode` writes MP3 320k (LAME tag), FLAC, ALAC or WAV and copies tags and cover art from the source.

## Invariants

- The last click lands exactly one click before the downbeat. `countin-verify` checks it: "vs planned" must stay at 0.00 ms.
- Stems come back sample-aligned with the input and of its shape. `test_stems_sum_back_to_the_mix_without_shift` guards it.
- Clicks never touch the song. A click that would push the mix past `CEILING` (0.98) gets turned down as a whole, by up to `LIMIT_DB` (12 dB); `render` counts the overs left after that.
- Models download once into the data folder (or come from an `assets` folder). The only other network traffic is the update check and the update download.

## Why these technologies

| Choice | Reason | Rejected |
|---|---|---|
| beat_this | best open beat/downbeat tracker, MIT code and weights | madmom: CC BY-NC-SA models, unmaintained |
| BS-RoFormer SW, one pass | six stems incl. guitar; keeps screamed vocals out of the guitar stem; about 2.5 min per 4-min song on MPS | Demucs htdemucs_6s: leaked vocals into guitar; two-pass RoFormer + Demucs: slower and worse |
| vendored RoFormer code | audio-separator pulled librosa, numba, onnx (~300 MB) and fetched files from the network | the audio-separator package |
| ffmpeg as a subprocess | every format, tags and cover art; arguments as lists, so any path is safe | Python codec bindings |
| LGPL ffmpeg build | GPL builds cannot ship in a closed bundle; LAME and mpg123 are LGPL | Homebrew ffmpeg (GPL, dynamic libs) |
| PySide6-Essentials | native look, LGPL, smallest Qt wheel | full PySide6 (adds WebEngine etc.) |
| sounddevice for preview | stems mix block by block, so sliders work live | afplay/winsound: no live mixing; QtMultimedia: needs PySide6-Addons |
| PyInstaller onedir | best torch support; onedir starts without unpacking 1.3 GB | onefile; Nuitka (slow, fragile with torch) |

## Multitrack export (`core/daw.py`)

- Save opens `ExportDialog`: two `OptionCard`s, a backing track as one file (`save_job`) or a multitrack folder (`export_job`). The chosen card shows its options: the output format for the backing track, the three file checkboxes for the multitrack, which always writes float WAV and MIDI. A line under the cards names the file or folder the choice writes (`target_path`, `multitrack_dir`). The choice sits in `export/*` settings and gets saved on Save only. Up and Down switch the card, Left and Right the format, Enter saves, Esc cancels; the layout's `SetFixedSize` resizes the window to the chosen card.
- The output format lives in `export/format` (empty follows the source). `export_format()` reads it for `Settings.fmt`; a `defaults/format` left by an older version counts until the dialog saves its own. The card defaults and the reset leave the format alone.
- Icon tiles and radio marks of the cards come from `option_pix`: the accent with `on_accent(app)` ink when chosen, grey otherwise.
- Output time 0 is bar 1. `daw.grid` adds even bars at the set tempo before the "1" marker until it reaches the song start and the earliest click.
- Song bars group beats in the chosen meter from the marker, not the detected downbeats: a stray downbeat in `bars_from` turned bars into 7/4 or 2/4. `song_beats` walks from the marker at the set BPM and takes the detected beat nearest one beat ahead, within a quarter beat, and adapts the beat length to it. Sections the detector counts at double rate keep the song tempo; real tempo changes come through. On the demo track the map went from 46–285 BPM over 138 bars to 81 BPM with one 95 BPM section over 99 bars.
- Pauses with their own tempo or meter splice in their zone bars. The last bar gets filled to a whole bar, so the meter holds to the end.
- The tempo map has a tempo and meter event on every bar line. Each tempo rounds against the time the MIDI has reached, so rounding never adds up. 6/8 is written as 6/8 with a dotted quarter per beat.
- `click.mid` carries the same tempo track plus GM drum notes on channel 10 (wood blocks for the count-in, closed hi-hat for pauses).
- Parts are the five separated stems at full level plus `other`, the mix minus them, so they sum back to the song. With parts off the folder gets one WAV with the turned-down parts taken out. They are 32-bit float WAV, because stems of a loud master peak above full scale. With a speed below 1 each part gets stretched on its own.
- `test_multitrack_click_and_audio_land_on_the_same_bar_grid` reads notes back through the tempo map and checks them against the placed audio. `test_tempo_map_follows_the_marker_meter_and_tempo_the_user_set` covers a moved marker, 3/4, 6/8 and doubled or halved BPM over wrong detected downbeats.

## App internals (`gui.py`)

- **Threads.** `Job` (`QRunnable`) runs work in two single-thread pools: one for analysis, one for preview and save, so they never compete for a model twice. `job.report()` sends progress and raises `Cancelled` when the user cancels. Separation reports once per chunk, which makes cancel take a few seconds.
- **Signals.** Workers only emit signals; slots are bound methods of `QObject`s created on the UI thread, so Qt queues them onto it. Do not connect worker signals to lambdas.
- **Waveform.** `Wave` caches the waveform layer in a pixmap keyed by view and size, painted with numpy straight into a `QImage` (one peak per device-pixel column, about 6 ms; a point-by-point polygon took 70 ms per zoom step). Repaints during playback only draw lines over it, and only the beats and clicks in view. A Python loop per repaint starved the audio callback and made preview crackle; keep the cache. The wheel zooms in proportion to the scroll, sideways trackpad scrolling pans.
- **Progress.** Three displays share one look (`QFrame#busyCard`). A blocking job (preview, save) veils the waveform (`Wave.overlay`) and shows a centred card with what runs, why (`JOB_WHY`), percent, time left, a tip and Cancel. Analysis and background separation use `Window.show_busy`: a large centred `BusyCard` with a progress ring and `BUSY_WHY` text, which lets clicks through to the waveform. Four seconds into the separation it folds into `BusyPill`, a capsule at the bottom centre of the waveform ("Separating parts · 44% · ~0:24 left"); a click unfolds it for four seconds, and so does an action that has to wait for the stems, with a line saying it starts once they are ready. The warning line keeps its height, so nothing in the window moves.
- **Tips.** While anything runs, `Window._next_tip` picks a line every 7 s: a practical tip from `help.TIPS`; the music lines (`PHRASES`) are off until a better set is chosen. It shows in `TipCard` at the bottom left of the waveform, translucent and click-through, during analysis, background separation and blocking jobs. `Wave._place_overlay` gives it the room left of the centred card or the capsule: next to the capsule a narrow waveform moves it under the pause headers, next to a centred card it gives way to that card's own tip line. Everything hides when the app is idle.
- **UI thread.** Nothing heavy runs on it: decoding, analysis and the waveform peaks run in `analyze_job`; the backing mix, its peaks and the pause search in `mix_job` (`mix_pool`, a newer request makes an older result stale); separation in the child process; cache size and clearing in the preferences on a pool thread. On a 6.5-minute song the longest UI stall is about 0.1 s at opening and under 50 ms otherwise.
- **Stem cache.** Whole-song stems go to disk after a separation (`core/stemcache.py`: `~/Library/Caches/Count-In/stems`, `%LOCALAPPDATA%\Count-In\cache\stems`), 16-bit FLAC per stem under a hash of the file and the model settings, written in a background thread; reopening a song takes them from there in seconds. The oldest songs go past 3 GB. The preferences show the size and clear it.
- **Separation process.** The app separates in a child process (`core/worker.py`, multiprocessing spawn, audio in shared memory both ways): Core ML's predict holds the GIL for 1–3 s per chunk and froze the interface and the audio callback when it ran in the app's process. The process starts with the first track (`warm_models`) and keeps the models loaded. A preview excerpt is urgent: the whole-song job hands over between two chunks, the excerpt gets separated, the job carries on. The bundled entry scripts call `multiprocessing.freeze_support()`; any script that opens the app must guard its code with `if __name__ == "__main__"`. The CLI separates in its own process.
- **Background separation.** Once a track is analysed, `separate_job` separates the whole song in its own pool (`sep_pool`) and reports through `show_busy`, so the waveform stays usable. Save and the pause search wait for it (`_wait_for_stems`, `after_sep`) instead of separating on their own; Play and double-click play the original at once and switch to the parts when they arrive (`_separate_now`); when it ends, the waveform switches to the backing and the pauses get searched again.
- **Transport and navigation.** Under the waveform sits `Overview`, a mini-map of the whole song with the pauses, the "1", the play position and a frame for the visible part; dragging the frame scrolls, a click outside it centres the view there. Below it the transport bar (`Window._transport`) holds: back to the count-in (Home), previous pause (←), play/stop (Space), next pause (→), the position as time and bar, the "Pause fill" group set off by short vertical separators (− removes the current pause, a chip shows "2 of 3", + makes a pause of the bar under the playhead; round buttons like the tempo card's), zoom out, zoom in, whole track and "?" for help. A plain click on the waveform sets the playhead `Wave.play_t` on the nearest beat (⌥ places it freely) and Play starts from it; without a playhead Play starts from the count-in. `_go_pause` makes a pause current, scrolls to it and plays from the bar before it. The playhead is a line in the text colour with a head on the time ruler; during playback it follows `cursor_t`. Arrow keys and Home go through the application event filter and are left alone when a text field, spin box, slider or combo box has the focus, a popup is open or another window (Help) is in front.
- **Tempo card.** `Window._tempo_card`: a large frameless tempo field with round − and + steppers, "÷2", "×2" and a wide Tap pad; under a divider the first downbeat with its time and one-beat shifts; the detector's other candidate shows as an orange banner. The spin boxes get their font in code, because a style sheet border on a spin box without buttons leaves its text field a few pixels wide.
- **Help.** "?" under the waveform and Help → Count-In Help (F1, ⌘?) open the user guide on the site in the app's language (`site_url`: `/guide/` or `/ru/guide/`); Help → Project page opens the site's home page the same way. `help.py` holds `TIPS` (the tips card) and `HELP` (the guide's sections, built by `docs/build_site.py`) as Russian strings with English in `i18n.EN`.
- **Models.** Both models stay loaded for the life of the app (`lru_cache`). The separation model starts loading in the background when the first track opens (`warm_models`), so the first separation does not wait for it; "loading model" shows only when it really loads.
- **Close.** "Close" (⌘W) goes back to the drop page without quitting; jobs for the closed track get cancelled and their results ignored.
- **Preview volume and defaults.** The header's right card is titled "Output volume": the slider with its percent sets `Player.volume` (`playback/volume`), the speaker level only; files never see it. Under a rule along the card's bottom sit Open, Close and Save (`QPushButton#headBtn`, Save in the accent colour). The floppy icon in the backing-track card header (and the File menu); the round-arrow icon next to it restores the saved defaults, or the factory settings when none are saved, stores the count-in, part levels and trim under `defaults/`, and every new window starts from them.
- **Preview.** `preview_job` renders the whole song from the count-in with the clicks, and hands the part stems over as `(array, output offset)`, slices of the cache with no copies. `Player` mixes them in the PortAudio callback with the current slider gains (`latency="high"`, 2048-frame blocks), so a seek, a jump to a pause or marker, or a loop wrap only moves `Player.pos` (`Window._jump`). A rebuilt preview (an edit, a level that needs stems, a new speed or key) swaps the buffer of the running stream, so it carries on without a gap. Only while the parts are still being separated for a turned-down level does it render an excerpt (`PREVIEW_AFTER`, `PREVIEW_FROM`). `Player.loop` plays output samples round; `Player.ticks` mixes clicks live, which gives the bar of count-in before a mid-song start (`click/preroll`); `Player.solo` plays only the soloed stems. The progress card shows only for jobs longer than 300 ms. Excerpt stems are cached per track in `stem_cache` as `(first sample, stems)`; a save stores full-track stems there too.
- **Loop and sections.** A Shift-drag or ruler drag offers "Play in a Loop" or "Make a Hi-Hat Pause". L toggles the loop; the speed trainer (Playback menu) adds 5% every `TRAINER_LAPS` passes. M adds a named section marker at the playhead, keys 1–9 jump to the first nine, right-click on a marker renames or deletes it; markers go into `tempo.mid` as MIDI markers. The ruler counts bars; ⌘G goes to a bar. N and P walk the set list made by opening several files at once; PageDown and PageUp (page-turner pedals) play/stop and play again.
- **Song memory.** `core/songs.py` keeps what was set for each song under its content hash in the data folder (`songs/<hash>.json`): tempo, the "1", count-in, part levels, speed, key, click, the pauses the user made or edited, removed pauses, loop and markers. `_restore_song` applies it after analysis; changes save 0.8 s after the last edit and on close. Undo (⌘Z, ⇧⌘Z) steps through tempo, the "1", user pauses and markers; edits within 0.6 s make one step.
- **Key.** `analyze.detect_key` matches the song's average chroma against the Krumhansl-Kessler profiles (no model, about 0.3 s); the detector line shows it, and with a transposition the key it now plays in. The transport's "Key" group shifts ±6 semitones with the tempo kept (`render.stretch(semis=…)`), in the preview and in saved files (`_+2st`).
- **Loudness and stage mix.** The backing card in the save dialog can write the file at −14 LUFS (`render.loudness`, BS.1770-4 with the K-filter in the frequency domain; `render.normalize` keeps peaks at −1 dB, so a dynamic song may stay quieter) and as a stage mix with the click alone on the left and the music in mono on the right (`render.Rendered.click`). The multitrack can add `click.wav` (`render.click_track`).
- **Time left.** It comes from the chunk rate since the stage began, excluding the first chunk that carries model loading.
- **One track.** `Window.open_files` takes the first audio file it is given and replaces the current track; a stale analysis gets cancelled and its result ignored.
- **Files from Finder.** `App.event` handles `QFileOpenEvent` for files dropped on the Dock icon.
- **Space.** An application event filter plays or stops on Space unless the key goes to a text field or spin box, or a modal dialog is open.
- **Preferences.** `PrefsDialog` saves to `QSettings` at once: `output/dir` (empty means next to the source), `output/group` and the `output/artist|year|album` levels, `output/reveal` (open the folder after saving, on by default), `appearance/icon`, `appearance/language`. `io.organized_dir` builds the folder from source tags; `io.safe_name` keeps names valid on Windows.
- **Pauses (fill zones).** `zones.bars_from` builds bars from the whole-song beats and downbeats (one-beat bars from stray downbeats fold into a neighbour), so the hi-hat follows tempo drift and meter changes. With "Fill pauses with hi-hat" on (`fill/enabled`), `Window._auto_zones` searches by itself, and searches always run with each part at the lowest level it had on this track (`search_levels`, kept in `Track.search_levels`), so raising a part again, fully or partly, to check the hi-hat keeps the pauses, while a threshold change rebuilds the found ones; pauses the user made or edited stay (`Zone.kept`), and bars of removed pauses go to `Track.dismissed` so no search brings them back (`_set_found`, `_zones_edited`). The first search with stems fits the threshold to that mix once per track (`zones.auto_threshold`: Otsu split of bar levels above -40 dB, clamped to -40…-12 dB) and moves the slider. Bars count as quiet by their first three quarters, so a stray beat or pickup at the band's entry does not cut a pause short. It searches on analysis, and 0.5 s after the guitar, vocals or "Silence threshold" slider (`fill/threshold`, default `zones.QUIET_DB` -18 dB) stop moving. The first search with a stem turned down separates the whole song (`zones_job`); the stems stay cached, so later searches are instant and the waveform then shows the backing track instead of the original. `find_zones` marks bars that many dB below the song's average level; a quiet run that reaches the last bar is the ending and stays out. The level runs up to each bar's last beat, so a band that comes back with a pickup leaves that bar in the pause and the hi-hat plays up to the entry. A bar whose only sound is the band's last hit on its first beat joins the pause after it, so the hi-hat starts right after the hit. When the detector loses the beat inside a pause (bars of different beat counts or lengths, as in a guitar-only intro), `zone_bars` plays an even grid between the pause edges in the meter and tempo of up to four bars before the pause (the bars after it for a pause at the song start). Each `zones.Zone` may override tempo and beats per bar; `zone_bars` then plays a steady grid from the pause start. `zone_clicks` puts a closed hi-hat (`render.hihat_samples`, synthesized, no sample license) on every beat of the pause and nothing else: the stick count-in plays only before the song's first downbeat. Each pause's hi-hat takes the level of the music around it (`zones.zone_gain`: power average of two bars on each side from `Track.bar_db`, measured once at analysis, clamped to -15…+3 dB), on top of the count-in volume. "Build-up at the end of a pause" (`fill/buildup`, on by default) turns the last bar of each pause into a run-in like the build-up count-in: quarters, then eighths over its second half, the last three louder (`zones._build_up`). On the waveform each pause has a header (number, meter, tempo); clicking it opens `ZoneDialog`, and the current pause, drawn brighter, has a cross in its header that removes it. Right-click removes a pause or adds a one-bar one (next to a pause it grows that pause); each edge has a handle that grows under the pointer with a "drag along the bars" label, edges drag along bar lines and the edit lands on release; a plain click on the ruler does nothing, Shift-drag or a drag along the time ruler selects bars, makes them a pause and opens its tempo and meter. The "Silence threshold" slider sits right under "Fill pauses with hi-hat" in the backing-track card; the waveform shows the level as an orange band from the top and bottom at its right edge, the gap between them is the silence; while the slider moves the band covers the whole track (`Wave.threshold_full`). Edits and level changes during playback rebuild the preview and carry on from the same position (`_restart_preview`); muting a part in a preview that started without stems rebuilds it with them.
- **Speed.** The transport's "Speed" group (− percent +, 50–100% in 5% steps; below 80% the stretch smears the sound, which is fine for working out notes) slows playback and export with the pitch kept: `render.stretch` runs Signalsmith Stretch (`python-stretch`, MIT; transients stay within about 1 ms), `render.render(speed=…)` stretches the song and puts the clicks on the slowed grid unstretched, so they stay crisp. Previews render only their excerpt; when slowed they rebuild the song from its slowed stems plus the slowed rest, because a stretched song minus a stretched stem does not cancel (phases move), and the live subtraction must stay exact; song time = `play_start` + player position × `play_speed`. Next to it the tempo at that speed (`→ 96,8 BPM`, `_speed_bpm`). Saved files get an `_80pct` suffix.
- **Resets.** The round-arrow icon in the tempo card header brings back the detected tempo (`_reset_tempo`), the one next to "First downbeat" the detected "1" (`_reset_t0`), the one in the count-in card header the saved or factory count-in (`_reset_count`); the backing card's resets everything.
- **Following playback.** While a preview plays the view pages along with the playhead (`_tick`) unless the waveform or the mini-map frame is being dragged. A click on the waveform or on the mini-map moves the playhead; during playback it carries on from there at once (`playheadClicked` → `_seek`).
- **Window.** The first start opens maximized; later starts restore the last size and place (`window/geometry`). The title shows the song with its file icon on macOS. The drop page opens the file dialog on a click and lists recent songs (`recent/files`, also File → Open Recent).
- **Tap tempo.** "Tap…" opens `TapDialog`: the song plays from just before the "1", Space taps (timed by the wall clock, since the player's block counter is 43 ms coarse), and two beats after the last tap the song carries on with a click at the tapped tempo and phase. Apply sets the tempo; closing stops playback.
- **Status bar.** File format from `io.describe`, save status, the version (`v0.5.0`) and, when a newer release exists, a round blue download badge left of it.
- **Update check TLS.** `update.check` trusts the OS certificate store through `truststore`. The bundled Python's OpenSSL looks for certificates in a python.org-only folder, so without truststore HTTPS fails on most machines. The model download (`assets.download`) uses the same truststore context; without it 0.7.0 could not fetch the models on a clean Mac. CI runs `countin --check-update` from the bundle to catch that.
- **Self-update.** `update.can_self_update` needs the asset's `sha256` digest from the API and a frozen bundle in a writable folder outside App Translocation; otherwise the badge opens the download page. `update.download` streams the zip into `.count-in-update/` next to the bundle, hashes it on the way and unpacks it (`ditto` on macOS keeps symlinks and permissions). `update.install_on_exit` starts a detached `sh`/`cmd` helper that waits for the app's PID, renames the bundle to `.old`, moves the new one in, restores the old one on failure and relaunches. "Restart to Update" relaunches; quitting with a staged update installs without relaunching. `test_update_helper_swaps_the_bundle_after_the_app_exits` runs the real helper on both CI platforms.
- **Theme.** `style_sheet()` fills colour tokens in `STYLE` for light or dark appearance.
- **App icon.** The preferences offer a light (default) or dark icon, saved under `appearance/icon`; anything else means light. `apply_icon()` sets the window and Dock icon at run time. Finder and Explorer always show the built-in light ICNS/ICO.
- **Languages.** `i18n.py` holds the English text. Strings in the code are Russian and pass through `_()`; `_("… {name}", name=x)` formats. The preferences save `appearance/language` (`system`, `en`, `ru`); `system` picks Russian for a Russian system locale and English otherwise. The language applies at start, together with the number format, so a change needs a restart. Detector notes come from `analyze.py` in English and get translated only for the Russian UI. `test_every_ui_string_has_an_english_version` fails on any `_()` string missing from `i18n.EN`; add the English line when you add a string. Folder names for missing tags (`Unknown Artist`) follow the language too.

## Packaging

- `io.resource()` resolves `samples/` and `bin/` against `sys._MEIPASS` in a bundle and the project root in development.
- `io.tool()` finds ffmpeg/ffprobe in `bin/` by full path; nothing relies on `PATH`.
- `packaging/countin.spec` builds one bundle with two executables sharing its libraries: `Count-In` (app) and `countin` (CLI). It bundles `LICENSE` (MIT), the `samples/stick_*.wav` clicks (the rest of `samples/` is ignored local test audio), `bin/`, the light and dark PNGs from `assets/icons/` and the `countin` package metadata (the update check reads the version from it).
- `packaging/build_ffmpeg.sh` builds a static, audio-only LGPL ffmpeg on macOS. ffmpeg 7+ needs the `fd` protocol for `-` pipes. Windows CI downloads a BtbN LGPL build instead.
- **Models live outside the bundle** (`core/assets.py`), so app updates stay small: about 780 MB of weights download once. Each file is looked up in `COUNTIN_ASSETS`, an `assets` folder next to Count-In.app / Count-In.exe (a copy carried on a flash drive), the user data folder (`~/Library/Application Support/Count-In/assets`, `%APPDATA%\Count-In\assets`) and `models/` in a checkout. On first run `AssetsDialog` downloads the missing ones from this repo's `assets-v1` prerelease (the update check ignores prereleases), falling back to the original publishers, or copies them from a chosen folder; sizes and sha256 are pinned in `assets.FILES`. The CLI downloads them on first use. When a model changes, upload it to a new `assets-vN` release and update `RELEASE` and `FILES`.
- `packaging/fetch_models.sh` downloads the weights for CI and development and checks their sha256, falling back to the `assets-v1` release; `build_ffmpeg.sh` checks the ffmpeg tarball. Windows CI pins a dated BtbN build by hash; BtbN prunes old autobuilds, so a 404 there means moving the URL and hash to a newer one. CI caches `models/` keyed by the fetch script.
- The windowed Windows build has no stderr; `packaging/countin_app.py` points it at devnull before anything prints.

## CI and releases

- Pull requests that touch code build both platforms, run the fast tests, then run the bundled CLI on 12 s of synthetic clicks with separation and mp3 export. A broken bundle fails here, before packaging. PRs that touch only docs, the site (`docs/`) or the promo video (`promo/`), PRs that only change `version = "…"` lines (the release bump) and pushes to `main` build nothing; the `changes` job decides from the diff.
- Speed: uv, the models, macOS ffmpeg and the exported Core ML model are cached. PRs and tags restore only caches saved on main, so `cache.yml` fills them on main when their inputs change and weekly before they expire; its keys must match `build.yml`. A version bump changes nothing for them: the Core ML key hashes `uv.lock` without the project's own version, and `cache.yml` and `worker.yml` skip pushes whose only changes are `version = "…"` lines (`.github/scripts/changed.sh`). Release archives use zip level 1, which halves the libraries while the weights barely shrink. Higher levels save about 5% for four times the packing time.
- The app smoke test starts the bundled app offscreen with `COUNTIN_SMOKE=1`; it quits after two seconds and fails when the bundled icon is missing.
- Release: add the release to `src/countin/changes.py` (the site's changelog page and the app's What's New read it; no hidden features there), bump `version` in `pyproject.toml`, tag `v<version>`. A prerelease uses a version like `0.10.0rc1` and the tag `v0.10.0rc1`; the `release` job marks tags with `rc` as prereleases, so the update check never offers them. Builds check that the tag matches the version. When a PR run of this repository built exactly the tag's tree and passed (each PR's `changes` job uploads a `tree-<sha>` artifact), the `reuse` job finds it and the tag publishes its bundles without building (a manual run on the tag always builds); bump the version in the PR that carries the changes, since a version-only PR builds nothing to reuse. A separate `release` job runs after both builds pass, or with the reused run's bundles, and is the only job with write access; it attaches `Count-In-windows-x64.zip` and `Count-In-macos-arm64.zip` and names the release `Count-In v<version>`. `update.asset_suffix()` matches those names.
- Errors: the app logs to `count-in.log` in its data folder (`~/Library/Application Support/Count-In/Count-In` on macOS, `%APPDATA%\Count-In\Count-In` on Windows). Job failures, analysis errors and unhandled exceptions land there.
- **macOS signing.** Tag runs pass the macOS bundle, built or reused, to the `sign-macos` job. It imports the Developer ID certificate into a throwaway keychain, signs every Mach-O inside out with the hardened runtime (`packaging/sign_macos.sh`, entitlements in `packaging/entitlements.plist`: JIT and unsigned executable memory for Python and torch), notarizes through an App Store Connect API key, staples the ticket and re-zips; `release` publishes that zip. The secrets (`MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `MACOS_SIGN_IDENTITY`, `APPLE_TEAM_ID`, `NOTARY_KEY_P8`, `NOTARY_KEY_ID`, `NOTARY_ISSUER_ID`) sit in the `release` environment, which only `v*` tags may use, so PR builds stay unsigned. The Developer ID certificate expires in 2031. Windows builds are unsigned.

- Python tooling is uv: `uv sync`, `uv run pytest -m 'not slow'`, `uv run countin-gui`.
- Commits need a DCO sign-off (`git commit -s`). Work on a branch and open a PR.
- Test the timing path with `countin-verify` after touching `render.py`, `io.py` or `analyze.py`.
- After touching `stems.py` or the RoFormer code, run the slow test (`uv run pytest`).
- New output format: add it to `io.FORMATS` and `io._codec_args`, then extend `test_lossless_roundtrip_is_sample_exact`.
- MIDI patterns (`render.pattern_grid`) take only the notes: the file's tempo is ignored, notes are read in quarter-note beats and quantized to sixteenths or eighth-note triplets, notes at one spot merge into one click, empty leading bars drop, and the pattern fills whole bars ending at the downbeat. `tests/data/count-in-played-96bpm.mid` is a hand-played sample (96 BPM, an empty bar, up to 30 ticks off the grid) that the tests lay onto a 120 BPM song.
- New count-in pattern: add a grid function next to `buildup_grid` in `render.py`, a segment in `gui.py` and a choice in `cli.py`.

## Known limits

- The grid fits the first 16 beats only; live tempo drift and rubato are not followed.
- Intros without a beat push the first downbeat to where the beat starts; the user moves the marker.
- Windows separates on the GPU through DirectML when the machine has a hardware GPU; without one (a VM, the Basic Render Driver only) it runs on the CPU, several times slower than on Apple Silicon.
- The license of the BS-RoFormer SW weights is not stated by the author.
